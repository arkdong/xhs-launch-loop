# 合规与发布前检查

两个入口，规则相同：

- 发布方案：`content_plan.py check --id L1`。先查方案是否完整，再对导出的成稿做下面全部检查。
- 现成的草稿：`note_check.py 草稿.txt`。第一行是标题，其余是正文和 `#标签`。有错误时退出码为 1。

## 错误级（必须改）

| 类别 | 说明 | 改法 |
|---|---|---|
| 极限词 | 广告法禁止的绝对化用语：最好、第一、顶级、唯一、全网最、100%、百分百 等 | 换成具体事实：「我用过的三款里最顺手的」「回购了 3 次」 |
| 功效承诺 | 根治、治愈、无副作用、保证有效 等 | 只写个人体验和使用时长，不承诺结果 |
| 站外导流 | 微信、淘宝、拼多多、闲鱼、二维码、手机号、外部链接；「某宝」「tb」「vx」这类谐音和缩写同样算 | 改成「主页」「店铺」「评论区」等站内说法 |
| 虚假诱导 | 点赞抽奖、互粉、刷单 | 删除 |
| 长度 | 标题超过 20 字、正文超过 1000 字、标签超过 10 个 | 删减 |
| 占位内容（只在发布方案里查） | 任何位置留着「待补充」「TODO」「XX」「【请填写】」「同上」 | 换成真实内容；不知道的去问用户 |

## 警告级（建议改）

| 类别 | 说明 |
|---|---|
| 站外提及 | 抖音、快手、京东、天猫、公众号：提到其他平台容易被限流，不是必须就删掉 |
| 绝对化承诺 | 再也不、彻底解决、一劳永逸：对效果的绝对承诺，改成自己的使用结果 |
| 功效宣称 | 美白、祛痘、抗皱、防脱、减肥、消炎、纯天然、零添加：需要资质或依据，没有就只写使用感受 |
| 夸大表述 | 闭眼入、天花板、吊打、封神 |
| 套话 | 综上所述、赋能、众所周知 |
| 结构 | 标题没有钩子、结尾没有互动引导、段落超过 180 字、正文没有任何具体数字、第一句过长 |

正常搭配不会误报：「第一次」「唯一的缺点」「不是最好」「100%棉」「很治愈」「治愈系」等已在白名单里。出现误报时把那句话换个说法即可，不要为了通过检查去改词表。

## 词表和行业专用词

通用词表在 `assets/banned_words.txt`，每行 `级别|类别|词|提示`（提示可省略），级别只有「错误」和「警告」。

行业专用的词不要改技能自带的词表，写进数据目录的 `xhs_launch/banned_words.txt`，格式相同，检查时自动追加。例如保健食品：

```
错误|功效承诺|降血糖|保健食品不能宣称治疗作用
警告|功效宣称|增强免疫力|需要对应的保健功能批文
```

临时追加一份词表：`note_check.py 草稿.txt --words 文件`。

## 身份与利益相关

用这个技能的人多数是品牌方或店主本人。用普通用户的口吻发自家产品，容易被读者和平台当成软广，评论区一旦有人指出来，整篇的可信度就没了。

- 建档时如实记录身份（`--identity "品牌方"`）。档案里是品牌方、店主、员工，而正文和首评都没有说明时，`check` 会给出警告。
- 写法：在「我为什么能说」里直接写一句，例如「自家产品，团队 5 个人连喝了 7 天」「我是主理人」。直说身份再讲缺点，比装成路人更可信。用认证的品牌号、店铺号发布时可以不写。
- 收了报酬、拿了样品的内容要写明（「品牌送测」「合作」），商业合作按平台规则报备。报备这一步脚本查不了，要提醒用户。

## 配图与 AI 声明

- 产品外观以实拍为准。AI 画出来的产品和实物不一样，读者收到货会觉得被骗。
- 用了 AI 生成的图片，发布时在小红书发布页勾选内容含 AI 合成的声明。
- 不生成真实名人肖像、他人的品牌商标、竞品包装、虚假的使用前后对比、伪造的数据截图或聊天记录。

## 脚本检查不了、需要人工判断的

- 医疗、保健、金融、教育培训等行业有额外的资质要求，涉及时提醒用户自行确认。
- 不得冒充真实用户写虚假体验，不得生成虚假评论或刷量方案。
- 对比竞品时不贬低、不点名攻击。
- 平台规则会更新，词表只是底线，最终以小红书官方规则为准。
