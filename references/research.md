# 调研方法（阶段 ①）

调研只为回答一个问题：**这次发布用什么角度，验证哪一条假设？**
普通的调研报告止于「用户怎么说」；这里要多走一步，得出一个发布后能被数据证伪的决定。

## 1. 做多大

| | 轻量（默认，用户手动搜） | 完整（环境里有搜索工具） |
|---|---|---|
| 搜索词 | `research.py keywords` 给的 6 到 8 个 | 加 `--full`，再由你补同义词、行业黑话、头部品牌，共 8 到 15 个 |
| 每个词看多少 | 「综合」前 10 篇 | 「综合」和「最新」各前 10 到 20 篇 |
| 笔记总量 | 30 篇左右，最少 20 篇 | 50 到 100 篇 |
| 评论 | 2 到 3 篇高互动笔记的评论区，共 20 条以上 | 笔记数据自带评论时自动使用 |

产品还没上市时不要搜自家口碑；已经上市的加 `--launched --product "产品名"`。不要让用户手抄几百篇，轻量模式的量足够得出「线索」和一条值得验证的假设。

## 2. 数据从哪来

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 | 环境里已有的小红书搜索工具 | 直接调用，把返回结果原样存成 json 入库。本技能不安装抓取程序、不要账号和 Cookie：自动化访问有账号风险，决定权在用户。 |
| 2 | 用户从 App 或网页复制、导出的表格、截图 | 始终可用。复制的内容不用整理，截图由你转写。 |
| 3 | 联网搜索 | 只用来补充站外的测评、吐槽和竞品信息，写进结论时注明「站外」，不入库。 |

## 3. `research.py add` 认得什么

| 输入 | 样子 | 说明 |
|---|---|---|
| 搜索结果页直接复制 | 标题、作者、点赞数各占一行，一篇接一篇 | 自动识别。带「广告」「视频」字样、作者后面带日期都能处理；有的卡片多出一行时会提醒你核对 |
| 每行一篇 | `标题 | 作者 昵称 | 赞 1.2万 | 藏 800 | 评 56 | 粉丝 900 | 2026-11-01 | 链接` | 除标题外都可以缺；整份文件都是 `标题 | 昵称 | 数字` 时，第二列按作者处理 |
| 表格 | csv、tsv、Markdown 表格，有表头 | 表头中英文都行：标题、点赞、收藏、评论、粉丝、作者、发布时间、链接 |
| json / jsonl | 各种工具的导出 | 自动在嵌套结构里找字段和评论列表 |

- UTF-8 和 GBK（中文 Windows 的 Excel 导出）都能读。文件名写 `-` 表示从标准输入读。
- 标题原样保留：开头的数字、中间的「｜」都不会被删或截断。
- **缺的数字按未知处理，不当 0。** 多数笔记没有收藏和评论数时，只比点赞，并在报告开头说明。
- 同一篇笔记按链接里的笔记 ID 合并；没有链接时，标题几乎相同且作者不冲突才合并。重复入库不会重复计数。
- **入库后必须核对输出**：识别成了哪种格式、共多少篇、前三篇和最后一篇的标题、作者、点赞数对不对。有 ⚠️ 时尤其要看。不对就整理成每行一篇，用 `--replace` 重新入库。

截图怎么转写：每篇一行，照抄标题，不改字、不删开头的数字；作者和点赞数写在后面，例如 `5款护手霜一周实测｜打工人版 | 作者 小鹿 | 赞 800`；看不清的数字留空，不要估。

## 4. 读懂分析结果

`research.py analyze` 的每一节都是脚本计数的结果。全部用中位数，避免被单篇爆款带偏。

| 部分 | 怎么读 | 常见误读 |
|---|---|---|
| 数据说明 | 先看这里：多少篇有互动数据、用的是哪种口径、有没有按账号大小校正 | 跳过它直接看倍数 |
| 撞卖点 | 你的卖点已经有几篇在讲、最高的是哪篇。有人讲过不等于不能发，而是要讲出不一样的地方 | 「没有笔记提到」可能只是说法不同。脚本只认字面（原文和原文里连续 4 个字的片段，价格和规格不拆开），用 `--selling-terms "卖点=说法1/说法2"` 补上同义说法再查 |
| 角度供给 | 「供给少互动高」是机会。占比最高的角度是红海 | 角度是按标题里的说法归的（避雷、对比、测评、教程、征集、公告、答疑、长文、清单、种草、个人故事），归错的你来纠正。「其他」是没归类的笔记，不参与比较；不到 5 篇的角度不算机会 |
| 标题钩子 | 「可用」一栏为「是」、倍数 1.3 以上才值得试 | 这是相关不是因果，所以才要当作假设去验证。「各账号不一致」的不能用 |
| 需求缺口 | 评论里在意（吐槽 + 疑问）满 3 条，而标题回应它的笔记不超过 10% | 标题里出现同一维度的任何说法都算回应（平价、平替、十块钱都算价格）。缺口也可能是「没人关心」 |
| 低粉爆款 | 粉丝少于 5000 且赞过千，或赞粉比不低于 1 且赞过 300。靠的是内容，最值得模仿 | 大号的爆款不要模仿，那是账号的功劳 |
| 综合评分 | 互动分位 40% + 时效 25% + 赞粉比 35% | 分数只用来排序，不是质量结论 |
| 假设候选 | 每条都对应上面的一项计数，并且过了门槛。没有候选时会写明原因 | 样本不够时硬选一条 |

**互动口径**：八成以上的笔记赞、藏、评齐全时用「赞 + 2×藏 + 3×评」，否则只比点赞。

**账号大小的影响**：大号随便发什么互动都高，直接比互动数会把「大号常用的写法」误判成「有效的写法」。脚本按下面的顺序处理，报告开头会写明用了哪一种：

1. 笔记集中在少数几个账号（每个账号不少于 5 篇）：每篇的互动先除以它所在账号的中位数，再比较。比的是写法，不是账号。
2. 多数笔记有粉丝数：先看这批笔记里粉丝量和互动的关系有多强，再按这个强度扣除。
3. 粉丝数不全：不校正，并标 ⚠️。这时所有倍数只能当线索。

一种写法只有在不只来自一两个账号，或者在两个以上账号内部方向一致时，才标为「可用」。

## 5. 门槛

| 结论 | 最低要求 | 不够时 |
|---|---|---|
| 任何倍数 | 有互动数据的笔记满 20 篇 | 只列数字，不出假设 |
| 两组比较（用和不用某个钩子、视频和图文） | 每组满 5 篇 | 显示「样本不足」 |
| 钩子、角度「可用」 | 来自 3 个以上作者，或在 2 个以上账号内部方向一致 | 不进假设候选 |
| 痛点 | 有效评论满 20 条，同一维度吐槽满 3 条 | 标为「线索」 |
| 需求缺口 | 在意满 3 条，标题回应不超过 10% | 不标缺口 |

没过门槛的发现照样可以告诉用户，但要原样说成「线索」，并说明再补多少数据能下结论。

## 6. 拆解对标笔记

对低粉爆款前 3 到 5 篇，逐篇记录（需要正文；没有就请用户粘贴）：

```
标题用了什么钩子：
前两行怎么开头（痛点 / 结果 / 反差 / 提问）：
正文结构（步骤 / 清单 / 对比 / 故事）：
有没有写缺点：
结尾怎么引导评论：
评论区最高赞在说什么：
我能照做的一点：
我要做得不一样的一点：
```

## 7. 写发布假设

格式：**「对 [人群]，用 [角度或写法] 会比 [对照] 的 [指标] 更高」**。

- 好：对早八打工人，用价格痛点开头会比上一篇泛卖点开头的评论率更高。
- 坏：这篇会火。（无法证伪）

一次只验证一个变量：角度、标题、封面、形式四选一。对照最好是自己的上一篇；以前发过的笔记用 `launch_log.py add --baseline` 登记并录入数据，就能当对照。已被证伪的不再重复（见 `launch_log.py next`）。

## 8. 发布简报模板

```
产品 / 目标人群：
调研样本：N 篇笔记，M 条评论，时间窗，覆盖的搜索词
撞卖点：                  （谁讲过，我们讲得不一样的地方）
本次角度：                （依据：角度供给表的哪一行）
要回应的关注点：          （依据：哪些评论原话；是痛点还是线索）
对标笔记：                （学什么、不学什么）
发布假设：
主指标：点击率 / 评论率 / 收藏点赞比（选一个）
形式：图文 / 视频
不确定的地方：            （样本不足、没有粉丝数、推测）
```

## 9. 证据规则

- 数字来自脚本，观点指向笔记或评论原话。写完回读一遍，删掉没有来源的句子。
- 脚本没数到的东西（品类特有的说法、图片里的信息）：先把说法加进项目词表重跑（见 `feedback.md` 第 5 节）；还不够就由你人工清点，在结论里标明「人工计数」并附原话。不要把人工数的数字和脚本的数字混在一起。
- 评论区比正文可信；高互动笔记里可能有推广，用评论区交叉验证。
- 没拿到的写「未获取」，并告诉用户补什么能提高判断质量。不用常识冒充小红书数据。
- 观点矛盾时两边都列，不替用户抹平分歧。提醒用户数据含推广帖和幸存者偏差。
