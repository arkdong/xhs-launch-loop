# 使用示例

用户问「这个技能怎么用」「能做什么」「给个例子」时，用这里的内容回答。
`python scripts/guide.py` 会原样输出下面的各节。示例里的产品「冷萃咖啡液」和所有数字都是虚构的，只用来演示格式。

## 总览

**一句话**：把每一篇小红书笔记当作一次产品发布。发之前调研，发的时候有方案，发之后看反馈，再决定下一篇。

四个阶段可以从头走，也可以只用其中一个：

| 阶段 | 做什么 | 你只要说 | 你会得到 |
|---|---|---|---|
| ① 调研 | 看同类笔记和评论，决定这次用什么角度 | 「我想发冷萃咖啡液，帮我调研」 | 调研简报 + 一条待验证的假设 |
| ② 发布 | 定下发什么、每一页放什么 | 「帮我做这篇的发布方案」 | 3 个标题、逐页图文、正文、标签、配图提示词 |
| ③ 反馈 | 读评论和数据，判断假设对不对 | 「这是评论和数据，帮我看看」 | 评论洞察 + 数据诊断 + 结论 |
| ④ 迭代 | 决定下一篇发什么、产品改什么 | 「下一篇发什么」 | 下一次发布简报 + 产品改进清单 |

**第一次用，最快的三种开口方式**

- 从零开始：「我要在小红书发布【产品】，目标人群是【谁】，帮我从调研开始。」
- 已经有草稿：「帮我检查这篇笔记能不能发。」然后贴上草稿。
- 已经发了：「这是我上一篇的评论和数据，帮我复盘。」然后贴上内容。

**你需要自己做的只有三件事**：提供真实信息（价格、使用感受、缺点、实拍图）、在小红书 App 里点发布、把评论和数据贴回来。其余都由技能完成。

**想先看效果**：说「给我演示一遍」，技能会用示例数据把四个阶段跑完（`python scripts/guide.py demo`）。

想看某一个阶段的详细例子，说「调研怎么用」「发布怎么用」「反馈怎么用」「迭代怎么用」。

## ① 调研

**一句话**：看大家都在发什么、用户在问什么，然后只选一个角度和一条假设。

**你可以这样说**

- 「我想发冷萃咖啡液，目标人群是早八打工人，帮我调研。」
- 「这是我搜『咖啡液 避雷』的结果，帮我分析。」然后贴上搜索结果。
- 「帮我看看这几篇竞品笔记的评论区在聊什么。」然后贴上评论。

**需要你提供**

- 产品品类、目标人群（一句话就够）。
- 同类笔记：环境里有小红书搜索工具时技能自己搜；没有就由你粘贴搜索结果或截图，30 篇以上最好。
- 可选：2 到 3 篇竞品笔记的评论。

**你会得到**（节选自示例数据的真实输出）

```
角度供给   清单合集 10 篇，互动中位数是整体的 0.38 倍
           避雷踩坑 2 篇，互动中位数是整体的 3.02 倍   ✅ 供给少互动高
标题钩子   含数字 2.3 倍｜点名人群 2.2 倍｜分隔符｜ 0.5 倍
需求缺口   价格：评论提到 4 条，只有 1/24 篇笔记在标题回应   🎯 缺口
低粉爆款   「宿舍党也能喝的冷萃拿铁教程」赞 3400，粉丝 800
假设候选   以「价格」痛点开头的笔记，评论率会高于泛卖点开头
```

最后技能会请你从候选里**只选一条**假设，登记为发布 L1。

**对应命令**：`research.py keywords` → `research.py add` → `comment_insight.py` → `research.py analyze` → `launch_log.py add`

## ② 发布

**一句话**：把调研结论变成一份照着做就行的方案，细到每一页的文字和画面。

**你可以这样说**

- 「帮我做 L1 的发布方案，我想要更多评论。」
- 「帮我写一篇冷萃咖啡液的种草笔记，再给我配图提示词。」
- 「帮我检查这篇草稿能不能发。」然后贴上草稿。
- 「把这篇改成 30 秒的口播视频脚本。」

**需要你提供**

- 这次最想要什么：触达（更多人看到）、互动（更多评论）、收藏（被当作资料保存），三选一。
- 真实信息：价格、用了多久、一个具体结果、一个缺点、手头有哪些实拍图。技能会一次问清，不会替你编。

**你会得到**（节选自示例方案）

```
标题      打工人算账：一杯咖啡到底多少钱   （另有 2 个备选）
第 1 页   封面｜图上文字「一杯不到4块」｜画面：办公桌上一杯冰拿铁，旁边一条咖啡液和几枚硬币
第 2 页   痛点场景｜「排队15分钟 咖啡已凉」｜画面：早晨便利店门口排着长队
第 3 页   这是什么｜「3秒冷萃 一条一杯」｜使用实拍
……
正文      开头钩子、我为什么能说、要点、缺点与适合谁、结尾提问
标签      #冷萃咖啡 #打工人日常 #咖啡液测评 #早八续命
检查      通过（错误 0，警告 0）
```

每一页还有一条配图提示词，例如：

```
办公桌上一杯冰拿铁，旁边放着一条咖啡液和几枚硬币，主体居中偏下，上方三分之一留白放标题，
真实手机摄影质感，自然窗边光，配色：奶油白、咖啡棕、少量亮橙色点缀，竖版 3:4，画面中不要出现任何文字
```

环境能生图时技能直接生成；不能时把提示词文件交给你，复制到任意生图工具即可。最后由你在小红书 App 里发布。

**对应命令**：`content_plan.py new` → 填写方案 → `content_plan.py check` → `content_plan.py prompts` → `launch_log.py publish`
只检查现成草稿：`note_check.py 草稿.txt`

## ③ 反馈

**一句话**：把评论和数据变成结论：这次的假设成立、不成立，还是证据不足。

**你可以这样说**

- 「L1 发了三天了，这是评论，帮我分析。」然后贴上评论。
- 「曝光 12000，观看 1800，赞 96，藏 140，评 31，帮我诊断。」
- 「这是创作中心的截图，帮我看看这篇怎么样。」

**需要你提供**

- 评论：粘贴文本、导出的表格或截图都可以，20 条以上结论才可靠。
- 数据：曝光、观看、点赞、收藏、评论，分享和涨粉有就给。

**你会得到**（节选自示例数据的真实输出）

```
意图分布   提问 33%｜购买意向 29%｜好评 25%｜痛点吐槽 21%
痛点聚类   价格 4 条：“太贵了吧，一杯算下来比便利店还贵”
待回复     真的 3 秒就能溶吗，冷水也可以？｜怎么保存？开封后能放多久
数据诊断   点击率 15.0% 较好：封面标题的角度有效
           收藏点赞比 1.46，大于 1：用户把它当有用的资料
结论       证据不足：首次发布没有对照，本次评论率记为基线
```

反馈会分成两类：**内容反馈**（标题、封面、写法）进下一篇笔记，**产品反馈**（价格、口味、包装）进产品改进清单。

**对应命令**：`comment_insight.py` → `launch_log.py metrics` → `launch_log.py verdict`

## ④ 迭代

**一句话**：汇总所有发布过的笔记，告诉你下一篇发什么、产品该改什么。

**你可以这样说**

- 「下一篇发什么？」
- 「根据这几次的评论，产品该改什么？」
- 「帮我出一份复盘报告。」

**需要你提供**

- 不需要新信息，技能读发布日志。至少完成过一次 ③ 反馈。

**你会得到**（节选自示例数据的真实输出）

```
尚未验证的假设   L1：以价格痛点开头的评论率高于泛卖点开头
产品改进线索     价格：累计 4 条｜购买与物流：累计 3 条“包装漏了，客服也不回”
可做选题的问题   真的 3 秒就能溶吗，冷水也可以？｜0 糖是真的吗，配料表发一下
建议             把高频问题合并成一篇答疑笔记，这是成本最低的下一次发布
                 一次只改一个变量，否则无法判断假设是否成立
```

然后回到 ① 或 ②，开始下一次发布 L2。

**对应命令**：`launch_log.py next` → `launch_log.py report`

## 完整示例

一次完整的对话大致是这样（用户说的话在左，技能做的事在右）：

| 用户 | 技能 |
|---|---|
| 「我要发布冷萃咖啡液，人群是早八打工人。」 | 建档，生成搜索词，收集并分析同类笔记，给出 3 条假设候选 |
| 「选价格那条。」 | 登记 L1，问：这次想要触达、互动还是收藏？ |
| 「互动。」 | 生成方案骨架，一次问清价格、使用时长、缺点、实拍图 |
| 「59 元 20 条，喝了一周，单喝偏苦，有 3 张实拍。」 | 填好方案，检查通过，给出标题、逐页图文、正文、标签、配图提示词 |
| （在小红书发布，三天后）「这是评论和数据。」 | 评论洞察、数据诊断，给假设下结论并登记 |
| 「下一篇发什么？」 | 下一次发布简报和产品改进清单，开始 L2 |

想亲眼看一遍，运行 `python scripts/guide.py demo`：它用 `examples/` 里的示例数据依次执行上面每一步的脚本，在临时目录里运行，不联网，也不会改动你的文件。加 `--out 目录` 可以保留产出文件，加 `--full` 可以看完整输出。
